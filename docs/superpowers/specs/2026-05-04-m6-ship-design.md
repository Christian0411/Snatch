# M6 — Smoke pass + ship — design

**Status:** Draft 2026-05-04.
**Goal:** Sign, notarize, and publish Snatch v1.0.0 as a downloadable DMG on GitHub Releases. Run the §9 manual smoke checklist against a notarized install. Document the result.

## Motivation

The pre-M6 polish, tweaks, cursor-affordances, and edge-resize-fix milestones (`CLAUDE.md` lines 42-45) leave Snatch functionally complete and dev-signed. M6 is the final milestone: take the dev-signed build, wrap it in a release pipeline, certify it against the §9 checklist of the locked design (`docs/superpowers/specs/2026-04-30-snatch-design.md` §9), and publish it.

This is the last milestone before v1. After M6, Snatch is downloadable by strangers from a GitHub Releases page.

## Non-goals

- **Sparkle / auto-update.** Deferred to v1.1. v1 users update by re-downloading the DMG.
- **GitHub Actions / CI signing.** The release pipeline runs locally on the maintainer's Mac. Cert + notarytool credentials already live there. CI signing is a future concern only if there's a second maintainer.
- **CHANGELOG.md.** Per-release notes live in the GitHub Release body and a small per-version notes file (`scripts/release-notes-X.Y.Z.md`). No aggregated changelog until there's a v1.0.1 to compare against.
- **Custom-designed app icon.** The v1 icon is generated from the `camera.viewfinder` SF Symbol (matching the menubar idle-state icon). A real designed icon can replace it later without changing anything else.
- **Demo GIF / screenshots in README.** Out of scope for v1's README. Add later if useful.
- **DMG with custom background image.** The DMG layout is plain `hdiutil`: a window containing `Snatch.app` and an `Applications` alias side-by-side. Drag-to-install works without a custom background.
- **Mac App Store distribution.** Distribution is via Developer ID Application + notarization only.

## Decisions made during brainstorming

1. **Distribution format:** DMG (signed + notarized + stapled).
2. **Update mechanism:** none for v1. Manual re-download.
3. **Pipeline location:** local shell script (`scripts/release.sh`).
4. **App icon:** SF-Symbol-derived (`camera.viewfinder` on a dark rounded-rect background), generated by a committed script.
5. **License:** MIT.
6. **Smoke triage policy:** "B" — run the §9 checklist; for each failure, decide blocker (must fix to ship) vs. known-issue (file as GitHub issue, link from README "Known Issues" section if user-visible). Latency targets are blockers if elapsed > 1.5 × target (i.e., >150 ms hotkey-paint or >750 ms stop-notification, median of n≥5); otherwise known-issues.
7. **Latency measurement:** `os_signpost` intervals + `os_log` info lines; readable via Console.app or Instruments. Always-on (no debug-only flag).
8. **README scope:** minimal (~35-40 lines): title, pitch, install, usage, requirements, updating, license.
9. **Versioning:** `v1.0.0` is the first tag, matching the pre-existing `Info.plist` `CFBundleShortVersionString`.
10. **Decomposition approach:** phased by dependency (Phase 1 parallel-ready prep tasks → Phase 2 release pipeline → Phase 3 smoke + ship).

## Open pre-req

The repo at `/Users/starship/src/snatch` has no `origin` remote. Before tagging or `gh release create` can run, the GitHub repo must exist and be set as `origin`. Two options for how M6 handles this:

- **(a) Manual:** maintainer creates an empty `snatch` repo on GitHub via the web UI, then locally `git remote add origin <url> && git push -u origin main`.
- **(b) Scripted:** an early M6 task runs `gh repo create <owner>/snatch --public --source=. --push`.

Either works; the implementation plan will pick one. The `<owner>` field in the README install link is filled in once the repo URL is known.

## Architecture

### Phase 1 — Build artifacts (parallel-ready)

Five tasks with no dependencies among themselves; can be tackled in any order or in parallel:

1. **Signing config via xcconfig.** Add `Snatch-Release.xcconfig` at the repo root, referenced by the Release configuration of the Snatch.app target. Contents:
   ```
   CODE_SIGN_STYLE = Manual
   CODE_SIGN_IDENTITY = Developer ID Application
   DEVELOPMENT_TEAM = 8E765EZVAM
   PROVISIONING_PROFILE_SPECIFIER =
   ENABLE_HARDENED_RUNTIME = YES
   ARCHS = $(ARCHS_STANDARD)
   ONLY_ACTIVE_ARCH = NO
   CODE_SIGN_ENTITLEMENTS = App/Snatch.entitlements
   ```
   Debug config keeps `CODE_SIGN_STYLE = Automatic` and `CODE_SIGN_IDENTITY = Apple Development` — day-to-day dev workflow is unchanged. Verify the `Snatch` xcscheme is shared (`Snatch.xcodeproj/xcshareddata/xcschemes/Snatch.xcscheme` committed); if not, share it.

   Verify `vendor/gifski/libgifski.a` is universal (`lipo -info`); rebuild it via `scripts/build-gifski.sh` if it's arm64-only.

   The current `App/Snatch.entitlements` is correct and complete:
   ```
   com.apple.security.app-sandbox = false
   com.apple.security.device.screen-capture = true
   ```
   No additional hardened-runtime entitlements needed (Carbon `RegisterEventHotKey` works under hardened runtime as-is; gifski is statically linked so no `cs.disable-library-validation`; no JIT, no allow-unsigned-executable-memory).

2. **App icon.** Add `scripts/build-icon.sh` that:
   - Renders a 1024×1024 PNG via a Swift heredoc (AppKit + SF Symbol `camera.viewfinder`, white, heavy weight, ~62% of icon dim, centered on a `#1C1C1E` rounded-rect background with ~22% corner radius).
   - Runs `sips -z N N` to produce the 10 required sizes (16, 32, 32, 64, 128, 256, 256, 512, 512, 1024) into a temp `.iconset` folder.
   - Drops the PNGs into `App/Assets.xcassets/AppIcon.appiconset/` with the standard `icon_<size>.png` / `icon_<size>@2x.png` filenames and writes a matching `Contents.json`.
   - The 10 PNGs and `Contents.json` are committed to the repo. `build-icon.sh` is for regeneration if the design changes.

3. **MIT LICENSE.** Standard MIT text at repo root, copyright line: `Copyright (c) 2026 Christian Canizares`.

4. **README rewrite.** Replace the current 5-line stub at `README.md` with the ~35-line minimal version (title, pitch, install steps, usage, requirements, updating, license). The install-link `<owner>` placeholder is filled in once the GitHub repo exists.

5. **Latency instrumentation.** New file `Sources/SnatchKit/Diagnostics/LatencySignposts.swift` (~50 lines):
   - One `OSLog(subsystem: "co.snatch.app", category: "Latency")` and one `OSSignposter`.
   - Helpers: `beginHotkeyToPaint()` / `endHotkeyToPaint(_:)` and `beginStopToNotification()` / `endStopToNotification(_:)`. Each `end` ends the signpost interval and emits an `os_log .info` line with elapsed milliseconds.

   Instrumentation points:
   - **Hotkey → first paint.** Begin in `MenubarCoordinator.handleHotkey()`, very first line. End in `CropperView.draw(_ dirtyRect:)`, gated by a `pendingPaintMeasurement: Bool` flag set by `MenubarCoordinator` when the hotkey fires and cleared on first paint thereafter. The flag mechanism is needed because `CropperView` is pre-warmed and reused — every paint after the first would otherwise re-fire the signpost. `CropperView` reads the flag via a closure injected by `MenubarCoordinator`, keeping the SnatchKit→AppKit dependency direction.
   - **Stop trigger → notification.** Begin in `MenubarCoordinator.requestStop()` very first line (all three stop paths funnel through this method per `CLAUDE.md` line 41 — one instrumentation point covers overlay button, menubar click, and ⇧⌘6). End in the completion handler of `NotificationPresenter.show(...)`, after `UNUserNotificationCenter.add(_:withCompletionHandler:)` returns successfully.

   These stay in the shipping app — overhead is negligible (tens of nanoseconds per signpost, one log line per user action). Anyone reporting "feels laggy on my Mac" can be asked to capture a Console.app trace filtered to the Latency category.

### Phase 2 — Release pipeline

Depends on Phase 1's signing config and icon being in place.

**`scripts/ExportOptions.plist`** (committed):
```xml
<dict>
    <key>method</key>             <string>developer-id</string>
    <key>signingStyle</key>       <string>manual</string>
    <key>teamID</key>             <string>8E765EZVAM</string>
    <key>destination</key>        <string>export</string>
</dict>
```

**`scripts/release.sh`** — single shell script with `set -euo pipefail`. Invocation:
```
scripts/release.sh [--publish] <version>
```
- `<version>` is `1.0.0` (no `v` prefix; matches Info.plist convention).
- Without `--publish`: runs the full build + sign + notarize + DMG + staple pipeline locally, stops before any tag/push/release.
- With `--publish`: additionally creates a tag, pushes it, and creates a *draft* GitHub release with the DMG attached. Maintainer manually clicks "Publish" on the GitHub web UI after eyeballing the draft.

Pipeline steps (each blocks the next):

1. **Pre-flight.** Working tree clean, no staged changes, on `main`. `Info.plist`'s `CFBundleShortVersionString` matches `<version>` (script verifies — does not auto-bump; bumping is a separate manual commit so the version bump is reviewable). `security find-identity -v -p codesigning` shows a "Developer ID Application" cert. `xcrun notarytool history --keychain-profile snatch-notarize` succeeds (set up once via `xcrun notarytool store-credentials snatch-notarize`).

2. **Clean + archive.** `rm -rf build/`, then `xcodebuild -project Snatch.xcodeproj -scheme Snatch -configuration Release -archivePath build/Snatch.xcarchive archive`. Phase 1's xcconfig produces a Developer-ID-signed, hardened-runtime, universal binary.

3. **Export.** `xcodebuild -exportArchive -archivePath build/Snatch.xcarchive -exportPath build/export -exportOptionsPlist scripts/ExportOptions.plist`. Output: `build/export/Snatch.app`.

4. **Verify signing locally.** `codesign --verify --deep --strict --verbose=2 build/export/Snatch.app`. Catches nested-signing or entitlement misconfigurations before consuming notarization slots.

5. **Notarize the .app.** `ditto -c -k --keepParent build/export/Snatch.app build/Snatch.zip`, then `xcrun notarytool submit build/Snatch.zip --keychain-profile snatch-notarize --wait`. Blocks ~1-5 min. On failure, fetch log via `xcrun notarytool log <submission-id> --keychain-profile snatch-notarize` and abort.

6. **Staple .app.** `xcrun stapler staple build/export/Snatch.app`, then `xcrun stapler validate build/export/Snatch.app`.

7. **Build DMG.** Plain `hdiutil`, no custom background:
   ```
   mkdir -p build/dmg-staging
   cp -R build/export/Snatch.app build/dmg-staging/
   ln -sfn /Applications build/dmg-staging/Applications
   hdiutil create -volname Snatch -srcfolder build/dmg-staging \
     -format UDZO -ov "build/Snatch-${VERSION}.dmg"
   ```

8. **Sign DMG.** `codesign --force --sign "Developer ID Application: ..." build/Snatch-${VERSION}.dmg` (full identity captured from `security find-identity` into a script variable).

9. **Notarize DMG** (second notarization, ~1-5 min). Apple's recommended belt-and-suspenders flow: stapling both the .app (extracted-from-DMG case) and the DMG (downloaded-link case) means Gatekeeper passes offline in both scenarios.

10. **Staple DMG.** `xcrun stapler staple build/Snatch-${VERSION}.dmg`, then `stapler validate`.

11. **Final Gatekeeper check.** `spctl -a -t open --context context:primary-signature build/Snatch-${VERSION}.dmg` simulates first-open. Must pass.

12. **(Only if `--publish`)** Tag + draft release:
    ```
    git tag "v${VERSION}"
    git push origin "v${VERSION}"
    gh release create "v${VERSION}" \
      --title "Snatch ${VERSION}" \
      --notes-file "scripts/release-notes-${VERSION}.md" \
      --draft \
      "build/Snatch-${VERSION}.dmg"
    ```

**Failure handling:** `set -euo pipefail` aborts on any non-zero exit. Notarization failures print the submission ID and the `notarytool log` command needed to fetch the error JSON. Partial state (intermediate files in `build/`) is left on disk for inspection — a re-run starts with `rm -rf build/`.

**Idempotency:** Running twice for the same version overwrites `build/` artifacts but won't double-tag (`git tag` fails) or double-publish (`gh release create` fails if the release exists). Re-publishing requires explicit cleanup (`git tag -d`, `git push origin :refs/tags/vX.Y.Z`, `gh release delete`). This friction is intentional.

**`.gitignore`:** add `build/` (currently `.build/` from SPM is ignored but `build/` from Xcode + release.sh is not).

### Phase 3 — Smoke gate + ship

**Stage 1 — Smoke on the dev-signed build.** Most §9 items don't need notarization, only Developer ID + hardened runtime.

1. Build via `xcodebuild ... archive` + `-exportArchive` → `build/export/Snatch.app` (signed, hardened, but unstapled).
2. Drag the `.app` to `/Applications`. First launch: right-click → Open to bypass the unstapled-build Gatekeeper warning. (This is dev workflow, not user workflow — Stage 2 covers the user flow.)
3. With Console.app open and filtered to `subsystem:co.snatch.app category:Latency`, run all 10 items in §9 of the locked design:
   1. Cropper drag/resize/dimensions/Record/Space/Enter/Esc.
   2. ⇧⌘6 from idle, fullscreen video, other-app focus.
   3. Stop paths: hotkey-stop, menubar-click-stop, Esc-cancel.
   4. Permission flow: revoke → relaunch → trigger → modal → grant → relaunch → record.
   5. Notification + "Reveal in Finder" path.
   6. Clipboard: ⌘V into Slack, Discord, Finder, Notes, Mail.
   7. Visual quality at each scale preset.
   8. Hotkey latency (read from Console).
   9. Stop latency (read from Console).
   10. `kill -9` mid-recording → relaunch → no `*.partial` files on Desktop.

   **Triage as you go.** Blocker → fix in code → rebuild → retest. Non-blocker → file as GitHub issue, append to README "Known Issues" subsection if user-visible. Latency targets: blocker if elapsed > 1.5 × target (>150 ms hotkey-paint, >750 ms stop-notification, median of n≥5), otherwise known-issue.

**Stage 2 — Smoke on the notarized DMG.** Once Stage 1 is clean.

1. Run `scripts/release.sh 1.0.0` (no `--publish`). Produces stapled `build/Snatch-1.0.0.dmg`. ~10 min wait for the two notarizations.
2. Drag old Snatch from `/Applications` to trash to test from a clean state.
3. Open the DMG, drag `Snatch.app` to the `Applications` alias, launch from `/Applications`.
4. Verify macOS shows the standard "Snatch was downloaded from the internet, are you sure you want to open it?" dialog (Gatekeeper accepted), not "Snatch can't be opened because Apple cannot check it for malicious software" (notarization or stapling failed).
5. Run a short subset of §9 against the notarized build:
   - #1 cropper (drag, resize, record).
   - #2 hotkey (⇧⌘6 once from idle).
   - #4 permission flow (the new code-signing identity prompts fresh — walk through grant + relaunch).
   - #5 notification + #6 clipboard paste (one each).
   - #10 crash hygiene.
   - Latency #8/#9 already measured in Stage 1; not re-measured.
6. If anything fails: fix → re-run `release.sh 1.0.0` → re-install → re-test. Each round is +10 min for notarization.

**Document smoke results.** Append a "M6 smoke results" section to this design doc capturing: macOS version(s) tested, measured hotkey-paint and stop-notification latencies, list of any known-issue GitHub issues filed.

**Ship.**

1. Bump `Info.plist`'s `CFBundleVersion` (monotonic int) if needed; `CFBundleShortVersionString` already matches `1.0.0`. Commit alongside `scripts/release-notes-1.0.0.md` and the updated `CLAUDE.md` "Status" section marking M6 ✅ Complete.
2. Run `scripts/release.sh --publish 1.0.0`. Tags `v1.0.0`, pushes, creates draft GitHub release with the DMG attached.
3. Eyeball the draft release page on GitHub web UI: title, notes, asset attached.
4. Click "Publish release."

## Definition of done

1. `git tag v1.0.0` exists locally and on `origin`.
2. The GitHub Releases page for the repo shows `v1.0.0` (published, not draft) with `Snatch-1.0.0.dmg` attached.
3. Downloading that DMG to a Mac, opening it, dragging to /Applications, and launching produces a working app that records a GIF — confirmed by Stage 2 smoke.
4. `CLAUDE.md` "Status" section updated: M6 ✅ Complete with a link to this design doc.
5. `README.md` and `LICENSE` are committed at repo root with the install link pointing to the actual `<owner>/snatch` Releases URL.
6. The "M6 smoke results" section of this design doc is filled in.

## M6 smoke results

### Stage 1 — dev-signed Release build, in /Applications (2026-05-04)

- **macOS version tested:** macOS 14 (Sonoma) on Apple Silicon.
- **Hotkey-to-paint latency:** **median 13.8 ms** (n=13, range 5.6–62.3 ms; the 62.3 ms outlier was the first cold-launch trace, all subsequent samples ≤24.4 ms). Target was <100 ms — passed by ~7×.
- **Stop-to-notification latency:** **median 59.6 ms** (n=3, range 54.1–60.0 ms). Target was <500 ms — passed by ~8×.
- **§9 qualitative items:** all 10 pass (cropper interactions, hotkey from various contexts, three stop paths, permission flow, notification, clipboard paste, visual quality at all three scales, crash hygiene with no `*.partial` files left after `pkill -9`).
- **Known issues filed:**
  - [#1 Permission re-grant via Settings doesn't update running process](https://github.com/Christian0411/Snatch/issues/1) — user must quit and relaunch Snatch after granting Screen Recording in System Settings; the running process can't see TCC state changes. Workaround documented in the README "Known issues" section. Not a ship-blocker.
