# Snatch

A fast, simple, native macOS GIF recorder. Select a screen region, record, get a GIF — instantly.

## North star

Two things matter, in this order:

1. **Speed** — sub-second from "stop recording" to "GIF saved". No H.264 intermediate, no FFmpeg round-trip. Frames stream into the encoder during capture.
2. **Simplicity** — single Xcode project, minimal dependencies, no Electron, no web tech.

## Stack

- **Language/UI**: Swift + SwiftUI (menubar, prefs) + AppKit (transparent cropper overlay window)
- **Capture**: ScreenCaptureKit (GPU-backed `CMSampleBuffer`s, hardware-accelerated cropping via `SCContentFilter`)
- **Encode**: gifski (Rust, via C FFI) — per-frame palette quantization, streams frames as they arrive
- **Min OS**: macOS 14 (Sonoma)

## Non-goals (v1)

- Cross-platform (macOS only — do not add Linux/Windows abstractions)
- Video output other than GIF
- Cloud upload, sharing integrations, plugin systems
- Audio recording

## Workflow

This project uses Superpowers (`obra/superpowers`). Design-first: brainstorm → write-plan → subagent-driven-development → TDD where it pays off (encoder, frame pipeline, file I/O), manual smoke-test gates where it doesn't (cropper UX, hotkeys, menubar feel).

Cancel-from-recording is wired in the state machine + tested via `FakeRecordingPipeline` but not user-triggerable until M5 brings the Carbon Esc hotkey. The M3 `SnatchCropperCLI` target was renamed to `SnatchSessionCLI` (binary: `snatch-session-cli`); the `m3-cropper-ui` tag preserves the old name historically. `snatch-record-cli` now uses `ScreenRecordingPipeline` directly — no behavior change.
- **M5 — Menubar app + hotkey + pre-warm ✅ Complete** (tag `m5-menubar-app`). `Snatch.app` runs from the menubar with `LSUIElement = YES`; ⇧⌘6 hotkey via Carbon (pre-routed); pre-warmed cropper hits sub-100ms paint; partial-file sweep on launch; full Screen Recording permission flow (NSAlert + System Settings deep-link + relaunch dance); post-stop chain (notification + clipboard + recents) routed uniformly through `MenubarCoordinator.requestStop` so all three stop triggers (overlay button, menubar click, ⇧⌘6) save consistently; Carbon Esc cancel-during-recording (registered dynamically while `state == .recording`); Recent Recordings ▸ submenu (cap 5, missing-file filter); scale dropdown persisted to UserDefaults; SF Symbols icon set (camera.viewfinder / record.circle.fill / exclamationmark.triangle.fill); backpressure refactor of `ScreenRecordingPipeline` (real producer/consumer + independent encoder drain via `BridgeQueue.dequeueBlocking`; clears CMSampleBuffer Sendable warning). New `SnatchAppKit` SPM library shares CropperWindow / CropperView / RecordingOverlayWindow between `snatch-session-cli` (dev tool) and the Xcode App target. `Snatch.xcodeproj` at the repo root is the App-target home; the three CLIs (`snatch-cli`, `snatch-record-cli`, `snatch-session-cli`) stay in `Package.swift` as headless dev tools.
- **Pre-M6 polish ✅ Complete**. Cropper preview border switched from solid to dashed `[6, 4]` white; resize handles became 8pt white circles with a 1pt grey rim (click target unchanged at 12pt); recording border dropped to 60% red alpha and matches the cropper's `[6, 4]` dash; new `RememberRegionPreferenceStore` (default ON) gates the cropper's last-region pre-fill, exposed as a checkable "Remember Last Capture Area" item in the menubar (between Scale ▸ and Recent Recordings ▸). `RegionStore`'s persistence semantics are unchanged — toggling OFF and back ON is lossless.
- **Pre-M6 tweaks ✅ Complete**. Custom 16×16 white `+` `NSCursor` + screen-space x/y readout pill follow the cursor in selection mode (idle, dragging, and `.have(rect)` outside-rect) — visibility predicate `CropperState.shouldShowCrosshair` lives in SnatchKit with 7 unit tests; `CropperView` drives the cursor swap from every mouse event (cursorUpdate alone is too sparse) and warms `mouseLocation` in `CropperWindow.becomeKey()` so the readout appears immediately. New `AutoStartRecordingPreferenceStore` (default OFF, key `autoStartOnSelection`, mirrors RememberRegionPreferenceStore) gates an "Auto-Start Recording on Selection" menu item that's disabled-and-unchecked when Remember is ON; auto-fire is constrained to fresh-drag commits via a `wasDragging` snapshot in `mouseUp` so resize-end never re-triggers. Record / Stop buttons replaced with custom-drawn dark pills (70% black / 85% pressed, 6pt radius, white 13pt semibold title drawn manually — no `super.draw`, no `wantsLayer`) for visibility against arbitrary wallpapers and app backgrounds.
- **Pre-M6 cursor affordances ✅ Complete**. New `CropperCursor` enum (8 cases) + `CropperState.desiredCursor(at:handleSize:isOverRecordButton:)` predicate in SnatchKit (19 unit tests), driving directional resize cursors over each of the 8 cropper handles and openHand/closedHand over the rect interior with gesture-lock semantics during `.resizing`. Diagonal `↘↖` / `↗↙` cursors come from `NSCursor+ResizeDiagonal` in SnatchAppKit, which calls private `_windowResize…Cursor` selectors guarded by `responds(to:)` with a `resizeUpDown` fallback (acceptable because Snatch ships via Developer ID, not the App Store). `CropperView.updateCursor()` and the x/y readout pill predicate both consolidated onto `desiredCursor`; `shouldShowCrosshair` survives as a one-line wrapper. Manual smoke matrix passed; `cursorIsOverRecordButton` now feeds the override at every cursor case (not just crosshair).
- **Pre-M6 cropper edge-resize fix ✅ Complete** (commit `080edb2`). Closes the long-standing AppKit/window-server quirk where the borderless `.screenSaver`-level `CropperWindow` accepted the macOS edge-drag resize gesture despite no `.resizable` in styleMask. Phase 1 diagnostic logging on `setFrame`/`mouseDown`/`mouseDragged` identified the AppKit path as `setFrame(_:display:)` (no mouse events fire — the system gesture writes straight into the window); Phase 2 added a `setFrame(_:display:)` override that always forwards a new `expectedScreenFrame` property captured at init. Code review caught a multi-display regression (`MenubarCoordinator.showCropper()` calls `setFrame(screen.frame, …)` to relocate the pre-warmed cropper to the cursor's screen, which the clamp would silently swallow on secondary displays) — addressed via a new `CropperWindow.resetToScreen(_:)` helper that updates `expectedScreenFrame` and bypasses the clamp. Verified by manual smoke matrix (4 screen-edge drags + handles + body-drag + new-selection + Esc/Enter/Space + Record + multi-display); all pass.
- **M6 — Smoke + ship ✅ Complete** (tag `v1.0.0`, https://github.com/Christian0411/Snatch/releases/tag/v1.0.0). Developer ID signed + notarized universal DMG (arm64 + x86_64) published to GitHub Releases. Stage 1 smoke (dev-signed in /Applications) covered all 10 items in §9; Stage 2 (notarized DMG, fresh install) covered the install + permission + clipboard + notification + crash-hygiene subset. Latency targets met by ~7-8×: HotkeyToPaint median 13.8 ms (target <100), StopToNotification median 59.6 ms (target <500), measured via the new `LatencySignposts` (`co.snatch.app/Latency` os_log + os_signpost) wired into `MenubarCoordinator.handleHotkey()` (`.idle` arm) and `requestStop()`. App icon generated from `camera.viewfinder` SF Symbol via `scripts/build-icon.sh` (uses macOS 14+ `paletteColors` SymbolConfiguration for white tint — sourceAtop fill on opaque bg was the wrong primitive). Release pipeline lives in `scripts/release.sh` (build → sign → dual notarize → DMG → staple → optional gh release create --draft); signing config in `Snatch-Release.xcconfig` (Manual / Developer ID Application / hardened runtime / `ARCHS_STANDARD` / `ONLY_ACTIVE_ARCH=NO`). Spec: `docs/superpowers/specs/2026-05-04-m6-ship-design.md`. One known issue: [#1 permission re-grant doesn't update running process](https://github.com/Christian0411/Snatch/issues/1) — user must quit + relaunch after granting Screen Recording in Settings; documented in README. M5's M6-blocking pre-req `xcuserdata`-only Snatch scheme is now shared at `Snatch.xcodeproj/xcshareddata/xcschemes/Snatch.xcscheme`.

Mixed build: `Package.swift` (SnatchKit + SnatchAppKit + 3 CLIs) + `Snatch.xcodeproj` (App target depending on SnatchAppKit via Local Swift Package). `swift test` runs the SnatchKit suite; `xcodebuild -project Snatch.xcodeproj -scheme Snatch build` produces the dev-signed `.app`.
